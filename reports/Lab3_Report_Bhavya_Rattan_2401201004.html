💎 Question 2: Resource Allocation Module (Fractional Knapsack)

O(n log n) Time | O(n) Space

Given items with weights and values and a knapsack of fixed capacity $W$, the algorithm selects items based on the highest value-to-weight ratio ($r_i = v_i / w_i$). Because fractional portions are permitted, the greedy strategy is provably optimal via the Exchange Argument.

⏱️ Question 3: Task Scheduling Module (Activity Selection)

O(n log n) Time | O(n) Space

The goal is to select the maximum cardinality set of mutually compatible, non-overlapping activities sharing a common resource. The greedy choice is to always pick the activity that finishes earliest (Earliest Finish Time First), leaving maximum remaining time for subsequent tasks.

🗜️ Question 4: Data Compression Module (Huffman Coding)

O(n log n) Time | O(n) Space

Huffman coding constructs a variable-length prefix-free binary code tree by repeatedly extracting and merging the two lowest-frequency subtrees using a min-heap priority queue. Frequent characters receive shorter codes, while rare characters receive longer codes.

🧠 Question 7: Discussion, Matroid Theory & Key Observations

CO3 Analysis
Why Greedy Strategy is Provably Optimal: Through the exchange argument, any hypothetical optimal solution $O$ that diverges from the greedy solution $G$ can be transformed into $G$ step-by-step by swapping elements with lower greedy rank for elements with higher greedy rank without decreasing total solution value.
When Does Greedy Fail? (0/1 Knapsack Breakdown): When items cannot be divided fractionally, greedy fails. For instance, with capacity $W=50$, taking an item with weight 10 and value 60 (ratio 6.0) leaves remaining space 40, which may prevent packing two heavier items (weights 20 and 30, values 100 and 120, sum = $220 vs greedy $160). 0/1 Knapsack requires Dynamic Programming ($O(nW)$), as covered in Lab 4.

Practical Applications: 1. Cloud hypervisor resource slicing (AWS EC2 / GCP). 2. Automated university room and lab timetable scheduling. 3. Digital file compression engines (JPEG, MP3, GZIP).
